# 产品与界面设计

## 定位与首版边界

为步行、徒步、跑步和骑行用户，提供无需账号的本地轨迹工具。核心任务是「开始记录」「加载已有路线」「保存并带走数据」。默认进入地图，底部只有地图、轨迹两个入口，设置在右上角。

首版范围：记录/暂停/继续/结束、定位质量、基础统计、本地列表与详情、GPX 导入导出、加载一条参考路线。加载是地图叠加，不表示具备转弯导航或偏航提醒。离线底图下载放到阶段 4；无网记录与本地文件查看从首版支持。社区、商城、账号、训练课程、排行榜、热量估计不进入首版。

## 竞品启发与证据边界

以下依据 2026-10-08 可访问的官方介绍及开发者商店介绍；未进行四款 Android App 的真机逐屏审计。表中的设计取舍是本项目的归纳，不声称竞品当前页面结构完全一致，也不复制其品牌和图标。

| 参考 | 有依据的产品优点 | 山径的设计转化 |
| --- | --- | --- |
| 六只脚 | 轨迹浏览、离线地图、参考线路和沿途脚印连接户外行程 | 地图优先；实际轨迹为绿色实线、参考路线为紫色虚线；起终点标注；后续支持沿途标记 |
| 两步路 | 将户外地图、轨迹与导航结合 | 定位质量和底图可用性始终可见；加载路线后提供「查看全程」；无网不阻断记录 |
| 咕咚 | 多运动记录、运动数据反馈、语音陪伴 | 记录页突出距离和有效记录时长；跑步显示配速，骑行显示速度；语音反馈留到后续 |
| Keep | 运动工具、跟练与记录反馈形成明确任务流程 | 每个状态只有一个主要动作；完成后显示简洁摘要；本项目的大数字、留白是自主设计 |

参考来源：[六只脚开发者介绍](https://apps.apple.com/cy/app/id543465749)、[两步路官方介绍](https://www.2bulu.com/about/about_us.htm)、[咕咚官方产品页](https://www.codoon.com/h5/codoon-welcome/product.html)、[Keep 官网](https://www.calorietech.com/)。

## 页面规格

| 页面/状态 | 信息层级 | 操作 |
| --- | --- | --- |
| 地图待开始 | 地图 → 定位状态 → 运动类型 → 开始记录 | 导入 GPX、定位到我、设置；运动类型记住上次选择 |
| 记录中 | 地图轨迹 → 距离 → 有效时长/配速或速度 → 暂停 | 上拉数据面板看海拔和累计爬升；进入轨迹库不停止记录 |
| 暂停 | 明确「已暂停」及冻结数据 | 继续为主按钮，结束为次按钮；结束再确认，返回不结束 |
| 轨迹库 | 搜索 → 全部/已记录/已导入 → 轨迹条目 | 顶部导入；每项仅标题、日期、距离、来源；点入详情 |
| 详情 | 路线预览 → 标题 → 距离/时长/爬升 | 加载到地图、导出 GPX；更多中重命名/删除 |
| 导入预览 | 文件名、路线数量、分段/点数、警告 | 选择轨迹/路线，确认保存；取消不留半成品 |
| 设置 | 单位、记录精度、地图与存储、关于 | 不设账户页；离线地图入口阶段 4 才出现 |

记录中可加载参考路线，参考路线与当前记录永远是两个对象，不能覆盖当前记录。返回地图后仍显示正在记录的面板。应用启动优先恢复活跃记录；从详情返回保留列表搜索与滚动位置。

主要路径：地图 → 开始记录 → 暂停 → 结束确认 → 自动保存并打开详情。文件管理器「用山径打开」或轨迹库「导入 GPX」→ 预览 → 保存 → 详情 → 加载到地图。详情 → 导出 GPX → 系统选择保存位置。

## 视觉规范

- 浅色底 #F5F6F2，主要文字 #182B25，次要文字 #5A6860，主色深绿 #17634B，参考路线紫色 #7450A2。地图使用低饱和底图，轨迹需有描边以适应复杂地形。
- 8 dp 间距网格，页面边距 20 dp，卡片圆角 20 dp，按钮高度 56 dp，所有触摸目标至少 48 dp。
- 距离 40 sp，页标题 24 sp，正文 16 sp，辅助信息至少 12 sp；单位单独显示；等宽数字防止记录时跳动。
- 不仅用颜色区分状态：记录/暂停有文字，轨迹实虚线不同，起终点有文字及符号。
- 遵循系统字体缩放，200% 时数据区可滚动；支持 TalkBack，图标有标签；后续 Android 实现提供深色语义配色，不简单反转底图。
- 底部操作位于安全区域内，记录按钮单手可达；结束不依赖只有长按才能发现的操作。

## 空态、权限和异常

| 情况 | 界面反馈与行为 |
| --- | --- |
| 无历史数据 | 「第一条轨迹，从这里开始」，提供开始记录/导入 GPX |
| 未授予定位 | 查看与导入仍可使用；点开始时说明用途并请求；拒绝后显示重试与系统设置入口 |
| 无定位或仅粗略定位 | 明确显示等待定位/精度不足；不生成虚假点。开始会进入等待状态，可取消 |
| GPS 丢失 | 状态条显示信号丢失；不补直线；重新获得位置时建立新段 |
| 无网无缓存 | 「底图暂不可用，轨迹仍在记录」，继续显示轨迹和定位信息 |
| GPX 无时间/海拔 | 距离仍可计算；时长/配速/爬升显示「—」，绝不把缺失值当零 |
| 文件错误或超限 | 显示原因，保留原文件，不覆盖已有轨迹；可重新选择 |
| 存储写入失败 | 高优先级提示并停止接受新点，保存已提交数据；不得继续显示正常记录 |
| 强制停止/重启后 | 提示记录中断，显示最后保存时间，用户选择继续为新段或结束保存 |
| 删除 | 显示名称并确认；活跃记录不可删除，导入原始文件随所属文档无引用时清理 |

## 原型范围

`prototype/index.html` 演示待开始、记录、暂停、保存、列表、详情、参考路线、导入预览和设置。导入使用明确标记的示例数据；原型不访问 GPS、不解析真实文件、不生成实际 GPX。真正的导入导出按数据契约在阶段 2/3 实现。
